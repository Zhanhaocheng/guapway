名字已经开始糊了。有人写成 Grok Boat，也有人问 Cursor 被收购之后还算不算独立 IDE。我按开发者座位先把工作表面拆开，再看它们可能往哪长。SuperGrok 放在套餐这一侧：它决定你用 Grok 的钱能打开哪些服务，不把它写成「跟产品无关」。

这篇是讨论稿，不是评测。事实以 8 月中能核对的公开材料为准：[Grok Build 发布稿](https://x.ai/news/grok-build-cli)、[Grok Bot 发布稿](https://x.ai/news/introducing-grok-bot)、[x.ai 定价页](https://x.ai/pricing)、[Cursor 论坛公告](https://forum.cursor.com/t/introducing-grok-bot/168053)。定价阶梯、具体权益和重叠怎么买，后面另写。

## 先认三层工作表面

开发者日常里，真正上手的是这三个：

| 名字 | 它实际是什么 | 你坐在哪 |
| --- | --- | --- |
| Cursor | AI IDE，写代码、改代码、看 diff 的主场 | 编辑器 |
| Grok Build | 终端里的编码 agent，TUI / headless / CI | 仓库根目录 |
| Grok Bot | 带着云电脑的常驻同事，登录你已有的工具把活干完 | 消息线程 |

Cursor 解决「人还在场时怎么改代码」。Grok Build 解决「人可以走开的长循环」。Grok Bot 解决「代码仓库外面的活，也要落到真实工具里」。

SuperGrok 不跟这三层抢窗口。它是 SpaceXAI 在 Grok 一侧的套餐：同一条产品线，按档位打开聊天、Imagine、Build，到了 Heavy 再打开 Bot。Cursor 自己还有 Ultra、Teams Premium。两边卖的是同一组服务里的不同组合，所以会重叠。重叠怎么算，后面单独谈。

混用工作表面的后果很具体：你会用聊天框的预期去要求 Bot，或用 IDE 的预期去要求 Build，然后觉得「这东西不行」。不行的往往是表面选错了。

## 公司层已经在并，产品层还没并完

2026 年的背景不是几个工具碰巧同名，而是一条正在合拢的公司线。

xAI 并进 SpaceX 之后，对外常用 SpaceXAI。6 月 SpaceX 宣布用股票收购 Cursor 母公司 Anysphere，金额报道在 600 亿美元量级，原时间表是三季度内交割。到 Grok Bot 发布时，两边仍被写成「正在变成一家公司」——交易还没完全落完，产品已经开始共用账号、云电脑和发布节奏。

这解释了几个看起来奇怪的细节：

- Grok Bot 的下载和登录走 Cursor 体系，文档也写隐私设置跟 Cursor 账号走。
- Wes Bos 在 X 上说 Bot 的云电脑很像 Cursor 那套 VM：Chrome、终端、一直开着。
- Cursor 内部从 6 月底就在测通用办公 agent，代号 Sand；8 月 11 日对外的名字是 Grok Bot。
- 7 月 Cursor CEO 还在说 model agnosticism 仍是产品中心。Bot 发布时却挂在 SuperGrok Heavy 和 Cursor 的高阶套餐后面，名字也带 Grok。

所以现在的关系不是「Cursor 用了 Grok 模型」这么简单。更像：模型、算力、编辑器、云电脑、办公 agent 正在被收进同一条供应链，对外还留着两套品牌、两套结账页。

## 三层表面不会很快合成一个窗口

如果只看发布会，容易得出「以后只用 Bot」的结论。从写代码的路径看，三层表面各管一段，短期内更可能并排变厚，而不是互相吞掉。

**Cursor** 仍是人在场的界面。补全、行内改写、看 diff、在文件树里做决定，这些需要你的手还在键盘上。收购完成也不会让 IDE 消失——Fortune 500 里已经铺开的，是这个入口，不是一个新的聊天 App。

**Grok Build** 是 5 月 25 日上的终端 agent。官方说法：在仓库里规划、改文件、跑命令、开 subagent，也能 headless 丢进脚本。7 月 harness 开源。它和 Cursor 的关系，更像 Claude Code 之于某个 IDE：同一类工作，一种在编辑器里盯着，一种在终端里挂着。Grok 一侧从 SuperGrok 就能装；更高阶的并行，报道里多挂在 Heavy。

**Grok Bot** 不跟你抢仓库里的光标。它要的是 CRM、邮箱、日历、没有干净 API 的后台。入口是发消息，不是先画工作流。多个 Bot 能互相当路由，但[文档写明](https://docs.x.ai/grok-bot/overview)：它们共用一台账号级云电脑，登录态不是按 Bot 名隔离的。

一条能用的切分：

```txt
人还在场、要看 diff       → Cursor
人走开、活还在仓库里     → Grok Build
活要落到仓库外的真实工具 → Grok Bot
```

套餐决定你现在能打开其中哪几层。Grok 一侧走 SuperGrok 各档，Cursor 一侧走 Ultra / Teams。同一层服务可以出现在两边，这就是重叠。

## 我看好的方向，和我不看好的方向

看好的不是「四个名字合成一个超级 App」。看好的是层与层之间的交接变短。

1. **云电脑变成公共底座。** Bot 能 24/7 跑，是因为下面有一台不跟你笔记本绑定的机器。Cursor 已经在给 agent 供 VM。下一步很自然：Build 的长任务、Bot 的办公任务、IDE 里的后台 agent，共用同一套机器、权限和审计。对开发者，这意味着「在哪打开」会越来越不重要，「这台机器能碰什么」会越来越重要。
2. **编码 agent 和办公 agent 会互相交活，而不是互相替换。** 工程 Bot 复现 bug、开票、再交给调试 Bot——这已经是官方内部例子。缺的是稳定的交接协议：仓库状态、PR、预览环境、审批。做对了，Cursor / Build / Bot 是一条流水线。做不对，就是三个都在改同一份登录态。
3. **两套结账页会先并，品牌会后并。** SuperGrok 和 Cursor 套餐现在是两条进同一组服务的路。公司并完之后，最省事的是一个账号打开三层表面。名字可以继续叫 Cursor 和 Grok，套餐会收成更少的几张发票。哪些档位重叠、重复付了什么，后面再算。
4. **Bot 大概率会往下渗，像 Build 那样。** Build 已经从 early beta 走进更宽的 SuperGrok 功能表。Bot 现在还停在最贵的几档后面。算力账算平之后，中间档接到一个缩水版 Bot，比突然出一个大众价更像他们的节奏。

我不看好的，是三件事被宣传成已经成立：

- **模型中立会原样留在所有表面。** 编辑器里继续选模型，说得通。一个以 Grok 命名、又出现在 SuperGrok 顶档里的 Bot，默认不是中立货架。Shumer 的体验也对得上：Bot 不让你选模型，后端自己路由。
- **多 Bot 等于多租户安全。** 官方原话是不要把不同 Bot 当安全边界。未来如果企业版只加 SSO、不加机器级隔离，这层栈就很难进生产账密。
- **「agent 替你上班」会先发生在编码里。** 编码反而更需要人看 diff。真正先被交出去的，是重复的外呼草稿、CRM 回填、发票分拣。开发者要习惯：自己的主场仍是 Cursor / Build，被 Bot 改写的是周围那圈工具。

## 竞争会把这层栈逼向哪里

Bot 进场时，对面已经有 Claude Cowork 和 ChatGPT Work。Build 对面是 Claude Code、Codex CLI。Cursor 对面是整场 AI IDE。

SpaceXAI 的差异不在「也会点鼠标」，而在**分发**：Cursor 的开发者底座，加上 Grok 一侧用 SuperGrok 把聊天、Build、Bot 收进同一组套餐，下面再共用云电脑。短处也在这里。Grok 在企业侧的份额，公开报道里一直偏瘦；Bot 的企业入口还是 waitlist。华盛顿和监管叙事会拖 IPO 故事，也会拖「把登录态交给 agent」这件事的信任。

所以未来两年，我预期他们会被迫选一条主叙事：

- 要么承认自己是 **开发者平台向外扩到办公**（Cursor 为根，Bot 是旁边的同事）；
- 要么承认自己是 **Grok 产品线向下接上开发工具**（套餐和模型为根，Cursor 是其中一个客户端）。

现在的发布顺序——先 Build，再 4.6，再 Bot——更像第一条。Bot 同时出现在 SuperGrok 顶档和 Cursor 高阶套餐里，又说明他们还不想现在就选死。

## 开发者现在怎么站

先按工作表面交活，再决定走哪条套餐。

已经在用 Cursor 写代码的，先把仓库内的长任务交给 Build 或 IDE 里的 agent，观察云电脑和权限模型。还没买到 Bot 那一档的，不必为了名字硬升；它还在 beta，文档自己都建议先只读、先出草稿。已经在付 SuperGrok 的，先看这档实际打开的是聊天、Build 还是 Bot，不要看名字里都有 Grok 就当成同一把钥匙。

一条可以留着的规则：

```txt
先认工作表面，再认套餐。
主场是 Cursor，长循环是 Build，出仓库是 Bot。
SuperGrok 和 Cursor 套餐是进这些服务的两条路，会重叠。
```

稿先写到这里。产品还在并，名字还会再糊一次。套餐怎么定价、一份钱里有哪些服务、两条路重叠在哪，后面再谈。下一篇如果要写产品本身，只补一件事：这三层表面第一次稳定地交过一次活。
